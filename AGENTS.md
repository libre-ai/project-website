# project-website Canonical Agent Rules

## Authority

Static bilingual catalogue of the Libre AI projects, a transverse repository of
the constellation. It renders, never decides: the portfolio is read from the
authority's `ecosystem/portfolio.v1.json`.
Doctrine lives upstream: https://raw.githubusercontent.com/libre-ai/project-governance/HEAD/AGENTS.md

## Boundaries

- Project names, groups and states belong to `libre-ai/project-governance`;
  `src/portfolio.ts` validates that portfolio at a fixed count and fails closed
  on any other shape. Change the count only together with the authority.
- The authority generation is pinned on two surfaces of
  `.github/workflows/code-validation.yml` (`uses: ...@<sha>` and
  `tooling_ref`); move both in one commit, never one alone.
- `site/*.html` are generated by `bun run sync:deployment-artifact`; never
  edit them by hand. `bun run build` writes `dist/` only.
- `docs/portfolio-material.json` is sealed by review digests: never modify it.
- No deployed service and no client JavaScript; deployment tooling under
  `tools/clever/` is not run for verification.

## Quality gates

Install through the local composition guide of the authority, then run
`bun run check` before pushing; never hide a red test.

## Agents

- Security > quality > performance > completeness, in that order on conflict.
- Stage files before running tree-walking gates.
- Never commit a machine-local absolute filesystem path.
